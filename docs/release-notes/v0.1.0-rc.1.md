# Pi Handoff v0.1.0-rc.1

**Experimental prerelease for a supervised pilot. Not production ready.**

This candidate includes Lots A–I and the Q2 security correction for missing or corrupt
renewal state. It is based on `f4206dbc9fcab89b666bc8623cbe8477f8bd7c95`; it does not
include the experimental Q3 branch.

## Highlights

- Safer schema-v3 checkpoint extraction, freshness and attestation, including read-only
  inspection and renewal guidance.
- Operator-supplied renewal tasks kept separate from predecessor notes and durable
  `Next action`; `renewal.successorTurn: "custom"` remains the default. The optional
  `"user"` mode remains experimental.
- Structured, hash-checked durable document edits and audit, less redundant checkpoint
  writing, and an optional supervised documentation-cycle workflow.
- Isolated mission instances with exclusive ownership, explicit closure, and
  operator-approved append-only knowledge publication.
- **Q2 fail-closed restoration fix:** absent, corrupt, incomplete or inconsistent chain
  state refuses renewal and related mutations instead of silently resetting
  authorization. Explicit new mission creation initializes a new mission-bound chain.

## Qualification limits

- Pi 1.5.2 real-runtime RPC was validated without inference.
- Pi 1.4.0 compatibility remains unqualified.
- Real renewals using the RC code and the documentation cycle with real inference were
  not qualified by Q3. These are evidence limits, not demonstrated failures.
- Q2 restoration scenarios validated fail-closed refusal for the measured missing and
  corrupt state cases.

## Installation and upgrade

Install from the immutable release tag after publication and verify that its commit
matches the release source commit. Copy the 12 extension modules as one directory, the
skill separately, and `scripts/durable_edit.py` only if the target project uses it.
Merge configuration manually. See [`docs/deployment.md`](../deployment.md) and
[`docs/upgrade.md`](../upgrade.md) for cold backup, hash manifests, recovery checks and
rollback.

There is no automatic migration, cleanup, chain reset or rewrite of scientific/project
state. Preserve `.pi-guard/`, external state directories, `.pi-handoff/` and all
project-specific operational/scientific evidence. `documentation.enabled` remains
`false` for the initial pilot; do not enable it merely because it ships in this RC.
